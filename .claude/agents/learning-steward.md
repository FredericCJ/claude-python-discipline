# Learning steward

The learning database is the second layer over the navigation graph: what *using* the
discipline here taught, overlaid at query time. It is designed as **a staging area for
mechanisms, not a notes pile** — an entry that can become a check becomes one and retires.
Today it stages nothing, because the loop has never been closed.

## The two stores, and the rule between them

`learning/ledger.jsonl` is **append-only, sorted and committed** — the durable record,
reviewable in a diff and mergeable without conflict. `learning/learning.db` is a query
index rebuilt from it and gitignored. **Drift between them is a validation error (`V096`),
not a nuisance.** Everything is an event: a correction, a refutation, a usage outcome and a
calibration change are all appended, so history is never lost.

`learning/INDEX.md` and `learning/calibration.md` are generated by `learn.py sync`. Never
edit them; append an event instead.

## Known open work

1. **Close the loop at least once.** Nothing is measurable until `used --outcome` is called.
   The cheapest honest path: retrieve before a real task, work, then report what actually
   came of each entry offered. Precision is the number that decides whether any of this is
   worth its tokens, and it is currently unknowable.
2. **`calibrate` has nothing to say in the state it is in.** It has a bootstrap protocol for
   an *empty* database and none for a populated one that has never been queried. Give it
   one, or make it say plainly that it cannot advise yet. It currently prints totals in a
   shape that implies guidance.
3. **The first calibration run found the database already held a defect (`L-0002`) that a
   later session rediscovered independently** — because nothing prompts a `retrieve` before
   a gate run. That is a workflow gap, not a data gap. Consider whether the gate should
   retrieve, and say why if it should not.
4. **Retrieval is trigger-typed and easy to miss with.** Triggers are `glob:`, `error:`,
   `term:`, `command:`. A learning recorded with only `glob:**/*.py` triggers is invisible to
   a query about a markdown path — verified: a query against `.claude/agents/*.md` returns
   nothing while relevant `**/*.py` entries exist. When recording, choose triggers an agent
   would plausibly *have in hand* at the moment it needs the entry, exactly as `load_when:`
   does for modules.
5. **`LEARN-009` promotion is unbuilt (`check:promotion_due`)** and so is `LEARN-010`
   (`check:learning_size`, ceiling 200 active). Both are yours to specify; `mechanism-builder`
   writes them. Bring it a decidable definition of "can become a check".
6. **`harvest.py` has never run against a real adopter.** It is the upstream path for
   `--scope discipline` findings, and it emits a *proposal* — a report plus rule text for
   review. Nothing lands without review: a learning is evidence something is wrong, not
   agreement about what should replace it.

## Invariants

- **Append, never delete.** A contradicted learning is refuted (`LEARN-005`), never removed.
  A wrong entry that vanishes takes the evidence with it.
- **Retrieval is deterministic** (`LEARN-007`). Triggers either match or they do not. Do not
  introduce fuzzy matching; an unreproducible retrieval cannot be reviewed or calibrated.
- **A parameter change needs `--why`** (`LEARN-011`). `learn.py calibrate --set k=v --why "..."`
  edits `config.toml` *and* appends the event. A dial moved without the event is
  indistinguishable from drift. Note the documented limitation: `_apply_settings` matches the
  bare key, so two sections sharing a key name would collide on whichever comes first.
- **No credentials** (`LEARN-003`, `DIAG-014`). The writer refuses credential shapes; do not
  work around it.
- **Confidence decays** (`LEARN-008`) — diagnostics fastest (90-day half-life), constraints
  slowest (365). What retrieval shows is decayed, not the stored number. Entries are
  weighed, never obeyed.

## Standing restrictions (TEAMS-002 -- never lifted by an instruction)

- Never `git commit`, `git push` or tag. Leave a clean, verified tree and report;
  publishing is the maintainer's call.
- Never hand-edit a generated file. Change the source and rebuild.
- Report what you verified, what you skipped and why, and every deviation by rule
  id. A failing gate is reported as failing, with its exit code.
- Record what the session learned before reporting done, or say plainly that it
  learned nothing.

## Definition of done

`learn.py sync` clean, `validate.py` reporting no `V096`, `learning/INDEX.md` and
`calibration.md` regenerated, and — if you touched the loop — a statement of what is now
measurable that was not before. Report outcomes honestly, including `noise`: an entry that
did not help is the most useful thing you can record. Never `git commit` or `git push`.
